# 图片加载链路（2026-11-06 改造后）

## 一条图从上传到显示

1. `POST /api/picture/upload` → `FileManager.uploadPicture`
2. 原图写 R2（`R2Manager.putObject` 写入 `Content-Type` 与 `Cache-Control: public, max-age=31536000, immutable`）
3. `FileManager.createPreviewImage` 生成长边 1280 的 `_preview.jpg`，同样写 R2
4. `ThumbnailManager` 逐档生成 `_preview_w240.jpg` / `_preview_w360.jpg` / `_preview_w640.jpg` 写 R2（源图宽度不足该档时跳过）
5. 前端 `utils/media.ts` 的 `thumbUrl()` 把宽度吸附到 240/360/640，直接拼 CDN 地址：`https://img.raylxpj.us.ci/<键>`
6. 浏览器 → Cloudflare 边缘 → R2（bucket `apic`，自定义域 `img.raylxpj.us.ci`，免费套餐）

## 各条链路

| 场景 | 地址 | 命中路径 |
| --- | --- | --- |
| 网格/胶片缩略图 | `https://img.raylxpj.us.ci/<stem>_preview_w{240,360,640}.jpg` | CF 边缘缓存（1 年）→ R2 |
| 预览图 | `https://img.raylxpj.us.ci/<stem>_preview.jpg` | 同上 |
| 原图 | `https://img.raylxpj.us.ci/<stem>.jpg` | 同上 |
| API | `/api/**` → VPS Nginx → backend | — |
| 兜底缩略图 | `/api/picture/thumb?key=..&w=..` | Caffeine → R2 预生成对象 → 现场生成并回写 |

## 实测（2026-11-06，China Mobile 出口，浏览器 20 张 w360 并发）

- CDN 冷（cache: reload）：**wall 324 ms**，单张中位 246 ms
- 同批走 VPS `/api/picture/thumb`（后端 Caffeine 已热）：wall 374 ms
- 后端重启后首次访问（Caffeine 空）：wall ≈ 1.4 s（每批 6 张 × R2 跨洋 ~240 ms）
- 浏览器缓存命中：20 张 5 ms（`immutable`，一年内不再发请求）

> CDN 的真正收益：不占 VPS 带宽、后端重启不受影响、HTTP/2 多路复用、浏览器按年缓存。首包延迟受「国内 → CF 边缘 ~200 ms RTT」限制，与直连 VPS 相当。

## 运维

- 历史对象补头（一次性，已完成 5158 个）：`copy_object(MetadataDirective='REPLACE', ContentType=…, CacheControl=…)`
- 新上传由 `R2Manager.putObject` 自动带头，无需再跑脚本
- 如果某张图缩略图缺失：前端会退到 1280 预览图；也可调 `POST /api/picture/thumb/backfill`（管理员）补齐
